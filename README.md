# Smart Traffic Management System (Simulation Prototype)

Noida Institute of Engineering & Technology (NIET), Greater Noida
B.Tech CSE (Artificial Intelligence), 2nd year - Operating Systems PBL

A Streamlit dashboard that **simulates** traffic control at one crossing with four approach roads
(J1 North, J2 East, J3 South, J4 West) and shows how Operating System concepts apply to it.

> **This is a simulation.** All vehicles, signals and emergencies are generated by software.
> It is NOT connected to real cameras, sensors or road signals. No API keys or paid services are needed.

## Setup (Windows CMD)

Install Python 3.10+ from python.org (tick "Add Python to PATH"), then:

```
cd smart-traffic-management-v2
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

The browser opens at http://localhost:8501. Press **Start** in the sidebar.

Run the tests without the browser:

```
python test_suite.py
```

## Files

| File | Purpose |
|---|---|
| `app.py` | Streamlit dashboard (only draws things) |
| `traffic_controller.py` | Signal rules, locks, deadlock prevention, safe emergency pre-emption, deadlock/race demos |
| `scheduler.py` | Pre-emptive priority scheduler with aging and Round Robin, plus demos |
| `simulation.py` | Producer and controller threads, IPC queues, vehicle generator, one-second step |
| `test_suite.py` | 7 tests that run the real simulation and report measured values |
| `data/sample_traffic.csv` | Sample simulated traffic: arrival rates per scenario |
| `logs/` | Log files (`traffic_log_*.txt`) and `test_report.json` |
| `.streamlit/config.toml` | Dark navy theme |

## Features

- Dashboard: 4 roads with vehicle count, density %, signal colour, countdown, overall Low/Medium/High status
- Start / Pause / Reset, scenario selector (Normal, High traffic, Rush hour, Night), speed control
- Green time grows with queue length (6 s + 0.8 s per vehicle, max 25 s); yellow 3 s; 1 s all-red
- North/South roads and East/West roads never get green together (checked every tick)
- Emergency button (ambulance / fire truck): current green is cut short through YELLOW and ALL-RED, then the emergency road gets green; red alert banner on the dashboard
- Charts: vehicle bar chart, density-over-time chart, intersection diagram, live event log, task scheduling table

## OS concepts and where they are implemented

| Concept | Where |
|---|---|
| Pre-emptive priority scheduling (Emergency 0, Signal 1, Density 2, Logging/Dashboard 3) | `scheduler.py` `_pick`, `_dispatch` |
| Aging | `scheduler.py` `_age` |
| Round Robin among equal priority | `scheduler.py` `_pick` (`last_run` tie-break) |
| Synchronization (Lock per signal, RLock for controller state) | `traffic_controller.py` |
| IPC (arrival, emergency and log `queue.Queue`s) | `simulation.py` |
| Threads (vehicle producer, controller) | `simulation.py` |
| Deadlock prevention (ordered locks + time-outs) and live demo | `traffic_controller.py` `ordered_locks`, `deadlock_demo` |
| Logging | `simulation.py` `_log`, `flush_logs` |

## Limitations

- One crossing, two phases; no turning lanes, pedestrians or vehicle physics
- One simulated CPU; the scheduler is a teaching model, not a real OS scheduler
- Arrival data is random (from `data/sample_traffic.csv`), not measured
- The simulation auto-pauses if the dashboard is not viewed for 2 minutes
